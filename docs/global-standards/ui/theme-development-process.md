# 新主题开发与设计流程规范

本文档规定了 AI 辅助开发「漫集」新主题时的标准流程、资产存放位置以及检查清单。所有新主题的开发必须遵循本规范，以确保与核心的 `manga-keep-ui-theme-style.md` 规范保持一致。

## 1. 文件存放位置规范

设计和开发一个新主题时，相关产出物必须按以下目录结构进行存放：

*   **主题设计文档**：
    存放在 `docs/global-standards/ui/themes/<theme-name>/<theme-name>.md`。
    文档内容应包含：主题设计理念（如“暖纸”、“樱花”等）、目标受众、Semantic Tokens（语义化色值）映射表、插画/助手角色使用说明等。
*   **主题原型图与设计素材**：
    存放在 `docs/global-standards/ui/themes/<theme-name>/assets/` 目录下。
    AI 生成的原型图、情绪板（Moodboard）、以及未来可能用到的空状态背景贴纸或角色小图标，均存放在该对应的主题资产文件夹内。
*   **代码实现文件**：
    存放在 `mobile/src/styles/themes/<theme-name>.ts`。

## 2. AI 开发新主题的标准流程

开发一个新主题应遵循以下四个阶段：

### 阶段一：设计与原型 (Design & Prototype)
1.  **明确主题意图**：与用户沟通，确认新主题的风格关键词（如偏向暗黑、小清新、高对比度等）。
2.  **生成原型/视觉参考**：AI 可以利用生图工具生成主题的 UI 原型或视觉风格板，存入 `docs/global-standards/ui/themes/<theme-name>/assets/` 文件夹。
3.  **起草设计文档**：在 `<theme-name>/` 目录下创建新主题的 `<theme-name>.md` 设计文档，定义所有的 Semantic Tokens（基础层、文字层、品牌操作层、状态层、反馈层），确保没有遗漏。

### 阶段二：用户审核 (User Review)
1.  **提交审核**：向用户展示原型图与 Token 映射表。
2.  **验证核心规范**：确保当前设计不违背《UI 主题风格设计规范》的底线（不能改变布局、不能改变状态按钮的位置和含义、必须保证文本的高对比度可读性）。

### 阶段三：代码实现 (Code Implementation)
1.  **编写 Theme 文件**：在 `mobile/src/styles/themes/` 下创建新的 TypeScript 配置文件。
2.  **实现 ThemeTokens 接口**：严格将设计文档中的色值转化为代码，必须 100% 实现 `ThemeTokens` 接口定义，不留 undefined。
3.  **接入系统**：在主题配置文件 `index.ts` 中注册新主题。

### 阶段四：验证与测试 (Verification)
1.  **视觉验收**：在代码层切换到新主题后，验证“书架总览页”、“条目详情页”、“补缺清单”这几个包含大量封面和标签的页面。
2.  **无障碍与对比度测试**：确保次级文字（`textSecondary`）和弱提示文字（`textMuted`）在当前背景（`background` / `surface`）下依然清晰可见。
3.  **状态色一致性验证**：检查“已有”、“缺本”、“想要”的颜色是否在当前主题下依然能被用户清晰区分。

## 3. 注意事项

*   不要直接在代码里用硬编码颜色测试，必须先写设计文档。
*   即使是“极简”主题，也必须提供完整的一套 Token，不可因为该主题下没有边框就省略 `border` 相关的 Token（可以用透明色或同底色替代）。
