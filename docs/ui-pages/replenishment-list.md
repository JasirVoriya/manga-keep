# 补缺清单页 UI 设计

本文档描述「漫集」补缺清单页的 UI 设计。该页面用于汇总缺本和想要条目，
帮助用户准备淘书、交换或求购。本文只描述页面自身排版和状态，不描述页面
跳转。

## 页面目标

补缺清单页必须快速告诉用户还缺什么，并把想要条目放在更高优先级。页面不
记录订单、价格、物流或卖家聊天，只服务轻量补完。

## 整体布局

页面采用单列工具页。背景使用暖纸色，内容以分组列表为主。信息密度中等，
适合用户在书市、二手平台或同好群中反复查看。

页面从上到下为：

1. 顶部统计和筛选。
2. 按目录或系列分组的清单。
3. 底部复制或导出操作。

## 顶部区域

顶部显示标题「补缺清单」。标题下方显示统计，例如「缺 12 项 · 想要 3 项 ·
3 个目录」。

右侧可放搜索或筛选图标。筛选条包含：

- 全部缺本。
- 想要优先。
- 编号范围。
- 已补齐。

筛选控件使用紧凑分段样式。

## 主要内容区

清单按目录分组。每组展示目录名、缺本数量和完成进度。组内条目包含：

- 编号、期号或卷号。
- 标题或条目标签。
- 出版类型。
- 当前状态。
- 备注摘要。

想要条目使用橙色标签，缺本条目使用低饱和提醒色。已补齐条目可以短暂以
淡化样式保留，方便用户确认。

条目以列表为主，不使用大封面网格。封面可以作为小缩略图，但不能挤占编号
和状态。

## 底部操作区

底部固定或贴底显示轻量操作：

- 复制清单。
- 导出清单。

当用户选择部分条目时，底部栏显示已选数量和复制/导出选中项。底部操作区
避开系统安全区。

## 状态呈现

清单状态包括全部缺本、想要优先、已找到和已补齐。状态变化必须即时反馈，
但不需要强动画。

如果条目带备注，备注用短标签或一行摘要展示。长备注通过展开查看，不撑高
默认列表项。

## 空状态和错误状态

没有缺本时，页面显示「当前没有缺本」，并补充说明用户可以从书架总览继续
维护收藏状态。

本地数据读取失败时，页面显示「本机数据暂时无法读取」，避免暗示云端数据
丢失。导出失败时保留清单内容，并提供重试。

## 移动端排版注意点

编号、状态和目录名优先清晰。长目录名最多两行。筛选条允许横向滚动，并露出
下一项边缘。列表项高度保持稳定，方便用户在实体场景中快速扫读。
