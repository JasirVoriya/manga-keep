# 条目详情页 UI 设计

本文档描述「漫集」条目详情页的 UI 设计。该页面用于查看并编辑单个漫画
出版物条目的收藏状态、品相和备注。本文只描述页面自身排版和状态，不描述
页面跳转。

## 页面目标

条目详情页必须让用户快速确认当前条目，并以低负担方式维护收藏记录。页面
重点是记录实体收藏，不展示漫画正文，不引导交易，也不扩展成复杂档案系统。

## 整体布局

页面采用上下分区：

1. 顶部为关闭入口、条目标识和状态。
2. 中部为封面与基础信息。
3. 下方为状态、品相和备注编辑。
4. 底部为保存操作。

视觉上像一张打开的收藏档案卡。背景延续暖纸色，信息组之间使用细线和浅色
底分隔，不使用过厚的卡片堆叠。

## 顶部区域

顶部左侧为关闭或返回按钮，右侧可放更多操作入口。中间显示条目标识，例如
「第 128 期」或「Vol. 12」。

标题区域必须保留编号完整展示。标题过长时最多显示两行，目录名和出版信息
放在标题下方，用较弱层级展示。

当前状态标签放在基础信息区附近，用户无需滚动即可看到该条目是已有、缺本
还是想要。

## 主要内容区

封面与基础信息采用紧凑布局。常规手机宽度下，封面在左，信息在右；窄屏或
大字号环境下，封面可以置顶，信息放在下方。

封面使用固定比例。没有封面时显示带编号的占位封面。基础信息包含：

- 条目标题。
- 目录名称。
- 期号、卷号或条目标签。
- 出版类型。
- 当前收藏状态。

编辑区域分为三个组。

收藏状态组使用三段式控件：

- 已有。
- 缺本。
- 想要。

品相组用于已有条目。可选值包含未标记、全新、良好、瑕疵和重复。当前状态
不是已有时，品相组降低视觉权重，但不强行删除，避免用户切换状态时信息
跳动。

备注组使用多行输入框。占位文案可以是「记录品相、来源、缺件或求购提醒」。
备注区高度适中，支持键盘弹起后的可见编辑。

## 底部操作区

底部固定保存栏位于安全区上方。主按钮为「保存」。当没有修改时，按钮可以
弱化；存在未保存修改时，按钮使用橙色或书架棕强调。

保存失败时，底部栏显示短提示「保存失败，请重试」，同时保留用户输入。
不在底部放交易、购买或阅读类入口。

## 状态呈现

状态在页面中出现两次：基础信息区的当前状态标签，以及编辑区的状态控件。
两者颜色和文案必须一致。

已有使用稳定的书架棕，缺本使用低饱和提醒色，想要使用橙色。状态不能只靠
颜色表达，必须有文字。

如果用户修改状态但尚未保存，页面显示「未保存修改」提示。提示靠近保存栏，
不要放在顶部让用户错过。

## 空状态和错误状态

条目不存在时，页面显示「未找到该条目」，保留关闭操作。

封面缺失时，显示占位封面，不影响状态和备注编辑。

本地记录读取失败时，页面优先展示条目基础信息，并提示「收藏记录暂时无法
读取」。保存失败时保留编辑内容，提供重试。

## 移动端排版注意点

状态和品相控件必须适合拇指点击。备注输入时，保存栏要避开键盘或转为键盘
上方操作。首屏必须能看到封面、编号、标题和状态控件，不能让封面过大挤掉
主要操作。
