# 应用更新提示页 UI 设计

本文档描述「漫集」应用更新提示页的 UI 设计。该页面用于在发现新版本时
说明更新内容、必要性和用户可选操作。本文只描述页面自身排版和状态，不描述
页面跳转。

## 页面目标

应用更新提示页必须清楚告知用户是否需要更新，以及更新会带来什么变化。语气
克制，不制造焦虑。

## 整体布局

页面可以作为独立页、弹窗或底部弹层内容。布局以版本信息和更新摘要为核心，
不使用大幅宣传图。

内容从上到下为：

1. 更新状态标题。
2. 当前版本和最新版本。
3. 更新内容摘要。
4. 操作按钮。

## 顶部区域

标题根据状态变化：

- 发现新版本。
- 当前已是最新。
- 需要更新后继续使用。

标题下方显示版本信息，例如「当前 1.2.0 · 最新 1.3.0」。强制更新时，标题
下方补充简短原因。

## 主要内容区

更新内容按分组列表呈现：

- 新增。
- 改进。
- 修复。

每条内容不超过一行半。强制更新需要明确说明原因，例如「此版本修复了本地
数据读取问题」。

如果检查失败，内容区保留当前版本信息，并说明「暂时无法检查更新」。

## 底部操作区

普通更新显示主按钮「更新应用」和次按钮「稍后」。强制更新显示主按钮「更新
应用」和次级说明入口，不提供继续使用入口。

已是最新状态只需要一个「完成」按钮。

## 状态呈现

状态包含检查中、可更新、已最新、检查失败和必须更新。检查中使用小型加载
状态。失败时不清空页面，保留当前版本。

强制更新可以使用更强的边框或标题强调，但不使用大面积红色警告。

## 空状态和错误状态

离线时显示「离线时无法检查更新，当前版本仍可使用」。检查失败时提供重试。
打开更新链接失败时，提示用户稍后重试或复制更新地址。

## 移动端排版注意点

版本号和按钮文案不能挤压。更新内容在小屏上使用纵向分组，不做多列。按钮
固定在内容末尾或弹层底部，保证拇指可触达。
