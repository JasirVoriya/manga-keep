# 书架总览页 UI 设计

本文档描述「漫集」书架总览页的 UI 设计。该页面是用户打开 App 后的主要
工作台，用于浏览目录、查看收藏进度、搜索筛选条目，以及进入收藏维护状态。
本文只描述页面自身排版和状态，不描述页面跳转。

## 页面目标

书架总览页必须让用户第一眼知道当前目录的收藏进度，并能快速回答三个问题：
我有哪些、我缺哪些、我接下来想补哪些。

页面气质是“实体漫画收藏册的数字索引”。它不是内容推荐页，也不是营销首页。
界面必须优先服务反复查看、快速筛选和批量整理。

## 整体布局

页面采用单列移动端结构，背景使用暖纸色。内容从上到下依次为：

1. 顶部品牌与目录区域。
2. 进度概览区域。
3. 搜索与筛选区域。
4. 封面网格区域。
5. 底部批量操作栏。

页面避免大面积装饰卡片。分区之间使用细分隔线、轻微色块和稳定留白，形成
纸质收藏册的秩序感。

## 顶部区域

顶部区域放在安全区内，保持紧凑。左侧显示 App 名称或页面标题，例如
「漫集」或「我的书架」。标题下方显示当前目录名称和一句短说明，例如
「知音漫客 · 704 期」。

右侧放置工具入口图标，例如目录、备份或设置。图标按钮使用统一尺寸，点击
区域不小于 44px。顶部不放大段文案，也不做首屏宣传。

当存在多个目录时，标题下方展示横向目录切换条。每个目录使用短名称标签，
当前目录使用书架棕底色和白字，其他目录使用浅纸色底和细边框。

## 进度概览

进度概览位于首屏上半部分，用低高度信息块展示：

- 已有数量。
- 缺本数量。
- 想要数量。
- 完成百分比。
- 横向进度条。

进度条使用固定高度，避免随数字变化跳动。已有使用书架棕，想要使用橙色，
缺本使用低饱和玫红或暖灰。数字必须比说明文字更醒目，但不使用夸张大字号。

## 搜索与筛选

搜索框位于进度概览下方。搜索框占满页面宽度，左侧为搜索图标，输入提示为
「搜索期号、卷号、标题」。右侧可以放清除按钮或范围筛选入口。

筛选条使用分段控件，包含：

- 全部。
- 已有。
- 缺本。
- 想要。
- 编号范围。

分段控件允许横向滚动。当前选项用书架棕或深暖色强调，未选项保持浅色。
筛选条高度必须稳定，不因文字变化撑高页面。

## 主要内容区

主要内容区为封面网格。默认密度以手机单手浏览为准，小屏可用 3 列，宽屏可
提升到 4 列或更多。每个条目卡片包含：

- 固定比例封面。
- 期号、卷号或条目标签。
- 简短标题。
- 收藏状态角标。

封面区域必须有稳定尺寸。封面缺失时显示带编号的占位封面，不能出现空白或
布局塌陷。标题最多两行，超出截断；期号或卷号必须完整显示。

状态角标固定在封面右上角或卡片底部标签区，不随标题长度移动。

## 底部操作区

底部操作区固定在安全区上方。常规状态下，左侧显示当前结果数量，例如
「共 248 项」，右侧显示主要操作「批量标记」。

进入批量相关状态时，底部栏切换为批量操作摘要，展示已选择数量和可用操作。
底部栏不能遮挡网格最后一行，页面底部需要预留安全间距。

## 状态呈现

状态颜色在全 App 内保持一致：

- 已有：书架棕实心标签。
- 缺本：低饱和玫红或暖灰标签。
- 想要：橙色或金橙色标签。
- 未标记：弱边框或无标签。

状态文案必须短，优先使用「已有」「缺本」「想要」。标签不使用图案代替文字，
避免用户只靠颜色理解。

## 空状态和错误状态

搜索无结果时，页面显示「没有匹配的条目」，并提供清除搜索或重置筛选操作。

筛选无结果时，页面显示「当前筛选下暂无条目」，并提供切回「全部」的操作。

公共目录加载失败时，页面保留内置目录和本地数据，顶部或进度区下方展示
非阻塞提示「公共目录暂时无法刷新」。提示不遮挡网格。

封面加载失败时，条目显示占位封面、编号和标题，收藏操作仍然可用。

## 移动端排版注意点

首屏必须露出一部分封面网格，让用户知道页面可直接浏览。搜索、筛选和进度
不能把网格完全挤出首屏。

所有可点击控件需要有明确触控区域。横向筛选条要露出下一项边缘，暗示可以
滑动。数字、编号和状态优先清晰，装饰元素必须让位给管理效率。
