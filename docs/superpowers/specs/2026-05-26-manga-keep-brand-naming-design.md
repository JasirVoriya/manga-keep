# 集漫品牌命名设计

本文档定义项目从旧命名收口到「集漫」的品牌与技术标识方案。这个方案
面向当前 MVP 阶段，目标是让 App 名称、仓库名、包名、存储标识、导出
标识和文档表达保持一致，并明确这次重命名不保留历史兼容。

## 背景

当前项目已经从单一《知音漫客》收藏册推进到漫画杂志收藏工具。现有命名
同时存在「知音漫客收藏册」、`comic-guests`、`com.comicguests.app` 和
`manga-shelf` 等标识，已经不能准确表达产品定位，也会增加后续发布、
备份、公共目录源和更新中心的理解成本。

新定位选择「漫画杂志收藏册」方向，气质结合怀旧纸刊感和轻二次元可爱感。
品牌名采用「集漫」，用「集」表达收集、收藏、补齐，用「漫」表达漫画和
漫刊。名称短、好记，适合系统桌面、启动页、图标、发布页和技术标识。

## 最终命名

新品牌统一采用以下命名：

- 中文显示名：`集漫`
- 完整说明名：`集漫：漫画杂志收藏册`
- 英文名：`MangaKeep`
- 仓库名：`manga-keep`
- Expo slug：`manga-keep`
- iOS bundle identifier：`com.mangakeep.app`
- Android package：`com.mangakeep.app`
- 导出 JSON `app` 字段：`manga-keep`
- 本地存储 key 前缀：`manga-keep`

App 内第一屏、系统桌面和图标旁只显示 `集漫`。README、发布说明、更新
中心、首次介绍和应用商店描述使用 `集漫：漫画杂志收藏册`，避免用户误解
为漫画阅读器或漫画内容聚合平台。

## 产品边界

「集漫」代表一个漫画杂志收藏记录工具，不代表漫画阅读、漫画下载、漫画
资源聚合或在线内容平台。命名和文案必须围绕这些核心能力展开：

- 浏览漫画杂志、画集、特刊等目录。
- 标记已有、缺本和想要。
- 统计收藏进度。
- 创建、导入和导出本地目录。
- 从公共静态源读取目录与封面信息。
- 通过更新中心获取新版本信息。

默认《知音漫客》目录可以继续作为内置示例和首个公共目录，但不能再成为
App 品牌名的一部分。

## 技术标识策略

所有面向新版本的配置和数据标识都统一为 `manga-keep`。实现时需要同步更新
以下位置：

- Expo 配置中的 `name`、`slug`、`ios.bundleIdentifier` 和
  `android.package`。
- 更新清单 URL、发布文件名和发布文档中的项目路径。
- 公共目录源示例里的项目名和地址示例。
- `AsyncStorage` 的收藏记录 key 和本地目录 key。
- 导出收藏记录和目录定义时写入的 `app` 标识。
- README、技术架构文档、功能盘点文档和可视化总览中的项目名。
- 代码、测试和样例数据中仍出现的 `comic-guests`、`manga-shelf` 和
  「知音漫客收藏册」品牌引用。

类型名、接口名和领域模型名不必在这次品牌重命名中全部改掉。比如
`ComicCatalog`、`ComicIssue` 仍然准确表达领域对象，可以保留，避免把品牌
重命名扩大成无关的模型重构。

## 清爽重构原则

这次重命名不保留历史兼容。旧版本仍处于 MVP 阶段，用户明确选择以全新
产品状态启动，因此实现时不迁移旧数据，也不兼容旧导出标识。

实现要求如下：

- 不读取 `comic-guests.collection.v1`。
- 不读取 `comic-guests.local-catalogs.v1`。
- 不兼容旧导出 JSON 中的 `manga-shelf` 标识。
- 不保留从旧纯数字收藏 key 到新目录 key 的迁移逻辑。
- 不在新文档中继续把 `comic-guests` 当作当前项目名。

旧标识只可以在迁移说明或历史说明中出现，不能作为新运行时路径的一部分。
重命名后的 App 会以空收藏记录和新本地目录存储启动。

## 用户体验

用户看到的核心表达要保持简单，但不能只像功能说明。`集漫` 面向的是有
纸刊记忆和补完欲的漫画杂志收藏者，因此首页文案需要带一点青春、回忆、
收藏和实体书仪式感。

- App 名：`集漫`
- Header 辅助文案：`把那些年追过的漫刊，好好收藏起来`。
- README 标题：`集漫：给漫刊收藏者的数字书架`。
- 更新弹窗和发布页：使用 `集漫` 指代 App。
- 导出文件说明：使用 `集漫收藏备份` 或 `集漫目录备份`。

「集漫」本身不解释功能时略泛，因此公共页面和长文档必须补充
「漫画杂志收藏册」这个说明名。App 内已经有目录、统计和收藏状态语境，
可以主要使用短名和共情型辅助文案。

可选口号可以围绕这些表达延展，但不作为首轮必须落地内容：

- `那些年追过的连载，值得被好好收藏。`
- `让你的漫刊收藏，从纸箱走进数字书架。`
- `缺哪本、收哪本、重复哪本，一眼看清。`
- `和同好一起，整理属于我们的漫画杂志记忆。`

## 数据流

新版本的数据流以 `manga-keep` 为唯一应用标识。收藏状态和本地目录写入新的
`AsyncStorage` key，导出 JSON 也写入新的 `app` 字段。导入时只接受新
格式或不依赖旧品牌字段的结构化数据。

公共目录、内置目录和用户本地目录的合并逻辑不因品牌重命名改变。默认目录
仍然可以是 `zhiyin-manke`，因为它是目录 ID，不是 App 品牌。

## 错误处理

由于不做历史兼容，旧数据不会自动出现在新 App 中。实现时不需要弹出迁移
失败提示，也不需要提示用户选择是否迁移旧数据。

导入旧备份时，如果备份带有不被接受的旧 `app` 标识，App 必须返回清晰的
导入失败原因。错误文案应说明当前版本只接受 `manga-keep` 格式备份，避免
用户误以为 JSON 损坏。

## 测试与验证

实现这次品牌重命名后，需要完成以下验证：

- 运行 `cd mobile && npm run typecheck`。
- 运行 `cd mobile && npm test`。
- 用桌面预览或模拟器确认 App 显示名、页面文案和导入导出流程正常。
- 按项目规则启动 `cd mobile && npm start -- --host lan`，用同一 Wi-Fi
  下的手机 Expo Go 扫码预览。
- 如果 LAN 预览失败，改用 `cd mobile && npm start -- --tunnel`。
- 如果真机预览仍无法完成，最终报告必须写明具体原因，不能称为完全验证。

## 非目标

这次命名设计不包含以下工作：

- 重新设计图标视觉。
- 新增目录管理能力。
- 发布真实公共目录源。
- 发布真实更新中心页面。
- 更改默认《知音漫客》目录的数据结构。
- 将所有 `Comic*` 领域类型重命名为品牌相关类型。

## 下一步

用户确认本文档后，下一步是编写实现计划。实现计划需要把配置、运行时存储、
导入导出、文档、测试和预览验证拆成可执行步骤，并确保旧命名不会残留在
新品牌的用户可见路径中。
