# 漫集 UI 主题风格设计

本文档定义「漫集」的整体 UI/UX 风格基调和多主题设计规范。它不固定具体
颜色，而是定义可复用的设计语言、语义化主题 token 和主题切换约束。

## 设计结论

「漫集」采用轻二次元可爱风的多主题收藏工具基调。

这意味着 App 的统一气质来自封面网格、贴纸化状态、收藏助手插图、轻快动效
和低负担工具布局，而不是来自某一套固定配色。用户未来可以切换多种 UI
主题，但主题切换不能改变信息结构、操作优先级和收藏状态含义。

一句设计准则是：

> 让用户感觉这是一个懂漫画收藏的人做的小可爱工具，同时仍然能高效查缺、
> 标记和备份。

## 风格关键词

整体风格使用这些关键词约束设计方向。

- 轻二次元。
- 可爱但克制。
- 收藏助手感。
- 漫画贴纸感。
- 封面网格主导。
- 低负担工具感。
- 主题可切换。
- 本地收藏可信。

这些关键词的优先级是工具效率高于装饰表现。可爱感服务亲和力，不能干扰
查找、筛选、批量标记和导入导出。

## 主题系统原则

主题系统必须把风格和颜色解耦。App 保持同一套组件结构、交互方式和信息
层级，不同主题只替换颜色、局部纹理、插图风格和少量装饰强度。

主题切换必须遵守以下规则：

- 主题不能改变页面布局。
- 主题不能改变按钮位置。
- 主题不能改变状态含义。
- 主题不能只依赖颜色表达状态。
- 主题不能降低正文、按钮和表单的可读性。
- 主题不能让危险操作在视觉上变弱。

每套主题都必须覆盖浅色、暗色或特殊风格下的完整语义 token。不能让页面
组件直接引用某个主题的具体色值。

## 语义化主题 token

UI 实现必须优先使用语义 token，而不是直接使用固定色值。下面是主题至少
需要提供的 token。

### 基础层级

基础层级 token 用于控制页面背景、容器和边界。

- `background`：页面主背景。
- `surface`：主要内容面。
- `surfaceSoft`：弱分区、浅色提示和表单底色。
- `surfaceRaised`：弹窗、底部栏和浮层。
- `border`：普通边框。
- `borderStrong`：强调边框和当前选中边框。
- `shadow`：浮层和卡片阴影。

### 文字层级

文字 token 必须保证主题切换后的可读性。

- `textPrimary`：主要正文和标题。
- `textSecondary`：说明文字和元信息。
- `textMuted`：弱提示、禁用说明和辅助信息。
- `textOnBrand`：品牌色按钮或标签上的文字。
- `textOnAccent`：强调色按钮或标签上的文字。

### 品牌与操作

品牌与操作 token 用于可点击元素、主按钮和页面强调。

- `brand`：品牌主色。
- `brandSoft`：品牌弱底色。
- `accent`：主要行动强调。
- `accentSoft`：行动弱底色。
- `focus`：键盘焦点和输入聚焦。
- `pressed`：按下态或选中态反馈。

### 收藏状态

收藏状态 token 必须在所有主题中保持含义稳定。

- `owned`：已有状态。
- `ownedSoft`：已有状态弱底色。
- `missing`：缺本状态。
- `missingSoft`：缺本状态弱底色。
- `wanted`：想要状态。
- `wantedSoft`：想要状态弱底色。
- `unmarked`：未标记或无状态。

状态 UI 必须同时使用文字和颜色。不能让用户只靠颜色理解已有、缺本和想要。

### 反馈与风险

反馈 token 用于保存、错误、导入冲突和危险操作。

- `success`：保存成功和完成反馈。
- `successSoft`：成功弱提示。
- `warning`：导入冲突和覆盖提醒。
- `warningSoft`：警告弱提示。
- `danger`：删除、清空和不可逆操作。
- `dangerSoft`：危险弱提示。
- `info`：普通说明和网络状态。
- `infoSoft`：说明弱提示。

## 组件风格规范

组件风格体现轻二次元可爱风，但必须保持工具可用性。

### 封面网格

封面网格是 App 的核心视觉资产。主题和装饰必须让位给封面、编号和状态。

- 封面比例稳定，加载前后不能造成布局跳动。
- 缺失封面使用主题化占位封面。
- 占位封面可以有轻二次元图形元素，但必须保留编号。
- 网格间距紧凑，适合反复扫描。

### 状态标签

状态标签可以设计成贴纸、小章或书签形态。

- 标签必须包含文字。
- 标签尺寸必须稳定。
- 标签不能遮挡封面主体信息。
- 同一状态在所有页面中使用一致的形状语言。

### 按钮

按钮保持清楚、轻快和可点击。

- 主按钮使用 `brand` 或 `accent`。
- 次按钮使用边框或弱底色。
- 危险按钮使用 `danger`，并与普通按钮保持明显区别。
- 按钮圆角保持适中，避免过度糖果化。

### 表单

表单用于目录编辑、备份导入和备注输入。表单必须比装饰更重要。

- 字段标签始终可见。
- 错误提示就近显示。
- 输入框边界在所有主题中清楚可见。
- 长文本字段支持稳定高度和键盘避让。

### 空状态

空状态是轻二次元可爱风最适合表达的地方。

- 可以使用收藏助手插图。
- 文案温柔但具体。
- 主操作必须清楚。
- 插图不能取代问题说明。

### 弹窗和底部栏

弹窗和底部栏用于高影响操作，例如保存、批量标记、导入覆盖和更新提示。

- 背景层级必须清楚。
- 主操作和取消操作必须区分。
- 危险确认必须写明影响范围。
- 可爱装饰在高风险操作中必须收敛。

## 插图与角色规范

App 可以使用一个轻量收藏助手角色来建立记忆点。角色适合出现的位置包括：

- 首次使用引导。
- 空状态。
- 备份成功。
- 补缺清单为空。
- 更新提示。
- 公共目录刷新成功。

角色不适合出现在每个表单字段、每个按钮旁边或高密度列表中。角色用于降低
冷感，不用于替代信息层级。

角色风格必须随主题适配。主题可以切换角色服装、装饰色或背景贴纸，但不能
改变角色在页面中的功能定位。

## 动效规范

动效必须短、轻、功能性明确。

- 保存成功可以有轻微弹性反馈。
- 状态切换可以有 150 到 250 毫秒的颜色或位置过渡。
- 进度变化可以使用短进度动画。
- 刷新和导入使用明确加载状态。
- 批量操作和危险确认不使用夸张动效。

所有动效必须支持减少动态效果设置。关闭动态效果后，状态变化仍然必须清楚。

## 主题示例方向

这些是未来可支持的主题方向，不是固定色值。

- 暖纸收藏主题：偏纸刊、书架和实体收藏。
- 樱花轻甜主题：偏轻二次元、柔和和亲切。
- 夜间书房主题：偏暗色、安静和长时间使用。
- 薄荷清爽主题：偏清新、低负担和工具感。
- 高对比主题：偏可读性、清晰边界和辅助访问。

每套主题都必须实现同一组语义 token，并通过可读性检查。

## 页面应用规则

不同页面可以使用不同装饰强度，但不能改变总体风格。

- 书架总览页以封面和状态为主，装饰轻。
- 条目详情页像收藏档案卡，装饰中等。
- 批量和导入页保持工具清晰，装饰弱。
- 补缺清单页强调查缺效率，装饰弱到中等。
- 首次引导和空状态可以使用最明显的角色与贴纸感。
- 帮助与关于页保持设置型信息页气质。

## 非目标

主题风格规范明确排除以下方向。

- 不把主题做成单纯换色皮肤。
- 不让主题改变功能结构。
- 不使用表情符号作为 UI 图标。
- 不把 App 做成漫画阅读器视觉。
- 不把可爱风做成幼稚风。
- 不在严肃操作中堆叠角色和装饰。
- 不让任何主题牺牲可读性和触控效率。

## 下一步

后续实现主题功能时，需要先把现有固定颜色迁移为语义 token，再为每套主题
提供完整 token 映射。页面文档中的具体 UI 描述应继续遵守本文档定义的整体
基调。
