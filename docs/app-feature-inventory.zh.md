# 当前功能与缺口盘点

这份盘点基于当前仓库里的代码和文档，重点看了 `README.md`、
`AGENTS.md`、`mobile/src/screens`、`mobile/src/components`、
`mobile/src/data`、`mobile/src/storage`、`mobile/src/update`、
`release/` 和 `docs/`。结论偏产品 owner 视角：哪些已经能给用户用，
哪些只是链路打通或文档预留，哪些还需要补。

## 结论

当前 App 已经从“单一《知音漫客》收藏册”推进到“通用期刊收藏统计工具”
的混合 MVP。用户可见层面已经能浏览期刊、切换目录、记录已有/缺本/想要、
筛选搜索、批量改状态、创建本地目录、导入导出 JSON、以及看到更新提示。

但它还不是完整上线形态。公共目录源和版本更新源在 `mobile/app.json` 里
仍是 `YOUR_NAME` 这类占位地址，代码会主动过滤这些地址，
所以真实远程目录和真实更新检测还没有发布配置。封面方面，代码支持远程
封面 URL 和静态 manifest，但当前包内仍保留并引用了 627 张本地封面，
还没有完成“不打包封面”的体积迁移。

## 已实现功能

下面这些功能已经在代码里形成用户可见闭环，不只是设计文档。

### 期刊浏览

主界面在 `LibraryScreen` 中使用 `FlatList` 展示当前目录的期刊网格。
默认目录是《知音漫客》，由 `defaultCatalog` 生成 1 到 704 期。

- 支持封面网格浏览，默认 4 列。
- 支持 3 到 8 列显示密度，用户可以用按钮调整，也可以双指捏合调整。
- 支持本地封面、远程封面 URL 和占位封面三种展示路径。
- 支持点按期刊打开详情弹窗。
- 支持长按某一期进入批量模式。

### 收藏状态

收藏记录保存在 `AsyncStorage`，存储 key 是
`catalogId:issueNumber`，例如 `zhiyin-manke:128`。当前版本只保留这种带
目录 ID 的限定 key，不承诺迁移旧格式数字收藏记录。

- 每一期支持三种状态：缺少、已有、想要。
- 已有状态支持品相：未标记、全新、良好、瑕疵、重复。
- 每一期支持备注。
- 点按期刊后必须在详情弹窗里保存，才会真正改状态。
- 状态变更会写入更新时间。
- 重启 App 后收藏状态仍然保留在本机。

### 统计进度

主界面顶部已经按当前目录计算统计。

- 显示已有数量。
- 显示缺本数量。
- 显示想要数量。
- 显示完成百分比和进度条。
- 统计跟随当前选中的目录变化。

需要注意：当前“缺本”是用 `总期数 - 已有数` 计算出来的，所以“想要”
本质上仍算在缺本里。

### 筛选搜索

当前 App 已经支持基础筛选和期号搜索。

- 可按全部、已有、缺少、想要筛选。
- 可按期号或期刊 label 搜索。
- 搜索框当前使用数字键盘，更偏期号搜索，不是完整标题全文搜索。
- 空结果有专门的空状态界面。

### 批量操作

批量模式已经可以在当前筛选结果内工作。

- 支持进入和退出批量模式。
- 支持长按某期进入批量模式并选中该期。
- 支持逐个勾选或取消勾选。
- 支持全选当前筛选结果。
- 支持清空已选。
- 支持把已选期刊批量标记为入库、缺本、想要。

批量模式还不支持输入范围，例如 `120-160`。

### 本地目录

本地目录已经是可用功能。相关实现主要在
`LocalCatalogEditorModal`、`localCatalogStorage` 和 `catalogHelpers`。

- 用户可以在 App 内新建目录。
- 字段包括 ID、名称、短名称、类型、总期数、补零位数和封面 URL 规则。
- 类型支持杂志、单行本、单册、画集、特刊。
- 本地目录保存在 `AsyncStorage`。
- 本地目录会和公共目录、内置目录合并后展示。
- 本地目录优先级最高，同 ID 时会覆盖公共目录或内置目录。
- 本地目录的期刊列表按总期数自动生成。
- 封面 URL 规则支持 `{number}` 和 `{padded}`。

### 公共目录源

公共目录加载链路已经实现，主要在 `catalogRegistry` 和 `catalogStore`。

- 支持从 `app.json` 的 `extra.catalogSources` 读取多个公共目录源。
- 按 `priority` 排序，主源失败后尝试备用源。
- 支持 registry 级别 `redirectUrl`，最多跟随 3 次。
- 支持 registry 指向多个 manifest。
- manifest 支持 `issueCount`、`numberPadding`、`coverBaseUrl`、
  `coverPattern` 和逐期覆盖字段。
- 相对 URL 会基于 registry 或 manifest 地址解析。
- 所有公共目录失败时，App 会回退到本地目录和内置目录。

当前限制是：`app.json` 里的公共目录源仍是占位地址，因此正式构建里还没有
真实公共目录发布源。

### 导入导出

工具弹窗已经把目录和收藏记录的 JSON 流程放到了同一个入口。

- 支持导出收藏记录 JSON。
- 支持从粘贴的 JSON 导入收藏记录。
- 支持导出当前本地目录定义 JSON。
- 支持从粘贴的 JSON 导入本地目录定义。
- 导入目录会校验 schema、ID、期数、补零位数和封面 URL 规则。
- 导入收藏会校验记录结构，并规范化旧 key。

当前导入导出仍是“文本框复制粘贴”形态，还没有接入系统文件选择、系统分享、
iCloud 或 Android 文件备份。

### 更新检测

自更新检测链路已经实现，主要在 `versionCheck` 和
`UpdatePromptModal`。

- App 启动时会尝试检查更新。
- 支持多个版本清单源，按优先级回退。
- 会过滤占位 URL，避免开发期一直请求无效地址。
- 支持比较当前版本和 `latestVersion`。
- 支持 `minimumVersion` 控制强制更新。
- 支持更新弹窗。
- 支持点击后打开 `updatePageUrl`。
- Android 会回退到商店链接或 APK 链接。
- iOS 会回退到 App Store 或 TestFlight 链接。
- 检查失败不会阻塞正常使用。

当前限制是：`app.json` 里的更新源仍是占位地址，所以真实版本检测还没有
发布配置。App 也不会在内部自动下载安装包，只会打开外部更新页面或链接。

### 发布和预览支持

项目已经有比较完整的发布说明和构建路径。

- `docs/release-and-updates.md` 说明了 Gitee Releases、自托管
  `version.json`、更新中心页面和 iOS 限制。
- `release/version.example.json` 给出了版本清单样例。
- `release/catalog-registry.example.json` 和
  `release/catalogs/zhiyin-manke/manifest.example.json` 给出了公共目录样例。
- `release/catalogs/zhiyin-manke/manifest.generated.json` 已经能作为远程
  manifest 雏形。
- `mobile/package.json` 提供了 `npm run typecheck` 和 `npm test`。
- `AGENTS.md` 要求涉及 App 行为、UI、导航、资源、发布配置或 Expo 配置
  的改动必须走桌面预览和手机 Expo Go 预览。

## 部分实现或预留

这些功能已经有设计、数据结构或部分代码，但还不能算完整上线。

### 不打包封面

已支持远程封面 URL、远程 manifest 和占位封面，理论上可以把封面放到
Gitee、GitHub Pages 或其他静态托管。

但当前包内仍有 `mobile/assets/covers`，并且
`coverSources.generated.ts` 仍在用 `require('../../assets/covers/...')`
引用本地封面。当前目录里有 627 张封面图，安装包体积迁移还没完成。

### 公共目录发布

公共目录读取能力已经完成，但真实公共数据源还没有配置。`app.json` 里的
地址仍是 `YOUR_NAME` 这类占位地址，代码会把这些识别为占位地址并过滤。

也就是说，App 现在能读公共目录，但还没有一个真实线上 registry 可以让
普通用户稳定拿到公共目录。

### 任意期刊统计

本地目录已经支持任意名称、类型、总期数和封面规则。公共 manifest 也支持
不同目录。主界面统计已经按当前目录计算。

但“任意期刊”目前主要适合规则化期号，也就是 1 到 N 的目录。还没有完整
逐期编辑器，不能在 App 里逐期维护标题、年份、刊期、合刊、增刊、排序或
不连续编号。

### 导入导出

JSON 文本导入导出已经可用，但还不是普通用户友好的文件流。

缺口包括文件选择、系统分享、备份文件命名、导入前预览、冲突处理选择、
导入未知目录记录时的提示，以及失败恢复体验。

### 目录冲突处理

`localCatalogStorage` 有冲突查找函数，`upsertLocalCatalogDefinition`
也能按 ID 替换已有目录。

但 UI 里没有“取消、替换、改 ID 导入”的选择。当前同 ID 导入会直接覆盖
本地目录定义。

### 更新中心

代码支持更新检测和打开链接，文档也定义了更新中心思路。

但仓库里还没有真正的静态更新中心页面，也没有真实 `version.json` 发布源。
Android APK 自分发路径有文档，iOS 只有 TestFlight、App Store 或侧载入口
预留。

### App 名称、仓库名和图标

`mobile/app.json` 当前名称是「漫集」，slug 是 `manga-keep`，包名是
`com.mangakeep.app`，图标文件也已经配置。

品牌已经批准为中文显示名「漫集」、英文品牌 `MangaKeep`、技术和仓库标识
`manga-keep`。完整实现由当前 rename plan 收口，目标是让 App 始终表达为
漫画杂志收藏册和纸质漫刊收藏数字书架，而不是漫画阅读 App。

## 尚未实现

下面按优先级分成必须补、建议补和以后再说。

### 必须补

这些是要把当前 MVP 变成可稳定分发版本时最先补的。

- 配置真实公共目录源：把 `app.json` 里的占位 `catalogSources` 换成可访问
  的 Gitee raw、GitHub Pages 或其他静态托管地址。
- 配置真实更新源：发布真实 `release/version.json`，并把
  `updateManifestSources` 换成真实地址。
- 做一个静态更新中心页面：至少放最新版号、Android APK 下载、更新说明和
  安装风险提示。
- 完成品牌落地：品牌已批准为「漫集」/ `MangaKeep` / `manga-keep`，继续
  收口图标、导出标识、发布说明和预览验证。
- 补目录导入冲突 UI：同 ID 时让用户选择替换、取消或改 ID。
- 完成手机预览验证：按 `AGENTS.md`，影响 App 的发布前检查必须覆盖桌面
  预览和真机 Expo Go 预览。

### 建议补

这些会明显提升可用性，但不一定阻塞第一版自用。

- 移除包内封面依赖：等远程封面链路验证稳定后，移除本地封面 `require`，
  只保留占位图和 UI 装饰图。
- 做原生文件导入导出：接入系统文件选择、分享面板和备份文件保存。
- 增加范围批量操作：支持输入 `120-160` 后一次性标记状态。
- 增加目录管理页：支持查看本地目录、编辑目录、删除目录和查看来源。
- 增加导入前预览：导入收藏或目录前展示数量、目标目录和覆盖风险。
- 增加真实公共目录投稿流程：定义提交格式、审核标准、封面托管规范和发布
  步骤。
- 补精确期刊数据：给默认《知音漫客》补年份、刊期、合刊、增刊等信息。

### 以后再说

这些适合等核心数据链路稳定后再做。

- 用户账号和云同步。
- App 内上传封面或公共目录。
- 任意远程订阅源 URL 的普通用户配置入口。
- 完整逐期编辑器。
- 淘书辅助：价格、来源、运费、订单状态、重复本、补缺优先级。
- App 内自动安装 APK。
- 完整应用商店接入和商店内更新流程。

## 按原始需求逐项对照

这一节把此前几个关键方向逐项落到当前状态。

### 不打包封面，改用图床或静态托管

当前状态：部分支持。

已支持的部分是数据和渲染链路。远程 manifest 可以提供 `coverBaseUrl`、
`coverPattern` 或逐期 `coverUrl`，卡片可以渲染远程 `coverUrl`。公共目录
样例和文档也已经按静态托管方案设计。

未完成的部分是体积迁移。当前 App 仍引用包内封面，并且包内仍有 627 张
封面图。要达到“不打包封面”，还需要发布真实远程封面、验证手机加载，再
移除 `coverSources.generated.ts` 对本地封面的依赖。

### 支持任意期刊统计

当前状态：基础支持。

用户可以新建任意本地目录，指定总期数和期号补零位数，然后按该目录统计
已有、缺本和想要。公共目录也可以通过 manifest 扩展到其他期刊。

限制是当前模型以 1 到 N 的规则化期号为主，不支持复杂逐期数据编辑。不连续
编号、合刊、增刊、年份刊期、特殊排序等还需要后续增强。

### 没服务器、不付费的数据方案

当前状态：架构支持，真实发布源待补。

设计和代码都走本地存储加免费静态托管。用户收藏、本地目录存在本机；
公共目录、封面和版本清单可以放在 Gitee、GitHub Pages、GitHub raw 或
类似静态托管上。App 不需要自有后端。

但当前配置仍是占位地址，还没有真实公共目录仓库、真实版本清单和真实更新
中心页面。

### 自更新检测和下载

当前状态：检测和跳转支持，下载安装到 App 内不支持。

App 能读取多个版本清单源、比较版本、识别强制更新并弹窗。用户点击后会
打开更新页面或平台链接。Android 可以通过外部页面下载 APK；iOS 预留
TestFlight 和 App Store。

还没完成的是：真实版本清单源、真实下载页面、真实 APK 发布资产，以及
App 内自动下载或安装。后者当前文档也没有把它作为第一阶段目标。

### App 名称、仓库名、图标

当前状态：品牌已批准，rename plan 正在收口实现。

现在 `app.json` 里已经使用「漫集」、`manga-keep`、
`com.mangakeep.app` 和图标文件配置。仓库和导出 JSON 的目标技术标识统一为
`manga-keep`，英文品牌为 `MangaKeep`。

文案需要继续围绕漫刊收藏、漫画杂志收藏册、数字书架和纸质漫画杂志收藏来
表达，避免把「漫集」误读成漫画阅读或内容聚合 App。

## 推荐下一步

建议先把“能自用、能小范围分发”的闭环打通，再继续做高级功能。

1. 完成 rename plan：把已批准的「漫集」/ `MangaKeep` / `manga-keep`
   落到图标、导出标识、发布说明和预览验证。
2. 发布真实静态数据源：至少发布一个公共 registry、一个《知音漫客》
   manifest、对应封面目录和一个真实 `version.json`。
3. 做更新中心静态页：先服务 Android APK 自分发，iOS 放 TestFlight 或
   App Store 占位说明。
4. 用真机验证远程目录、远程封面和更新检测：验证通过后，再移除包内封面。
5. 补导入冲突和文件导入导出：减少用户误覆盖和手动复制 JSON 的门槛。
6. 再补范围批量操作和精确期刊数据：这些会让收藏统计从“可用”变成“顺手”。
